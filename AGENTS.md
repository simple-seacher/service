# AGENTS.md — Search Service

## Назначение и источники требований

- Этот репозиторий предназначен **только для кода Go-приложения, тестов, миграций и инструментов качества/CI**.
- Единственный источник согласованных архитектурных решений и задач — отдельный Git-репозиторий `search-service-architecture` (Obsidian Vault).
- Каталог `.devcontainer/` — Git submodule репозитория `search-service-devcontainer`. Не изменяй его содержимое или зафиксированный коммит без явной инфраструктурной задачи.
- Репозиторий архитектуры **не монтируется в Dev Container автоматически**. До реализации получи содержимое утверждённой задачи `TASK-XXXX` и связанные ADR от пользователя или по доступной ссылке на конкретную ревизию. Если спецификации недостаточно — сообщи о пробеле, а не придумывай контракт.

## Правила работы Codex

1. Прочитай задачу, релевантные ADR, `git status` и затрагиваемые файлы.
2. Если запрос про анализ или проектирование — не изменяй файлы без явной команды.
3. При явно разрешённой реализации сначала кратко укажи план, затронутые файлы и проверки; затем выполняй только текущую задачу.
4. Не создавай заранее интерфейсы, API, пакеты, миграции и зависимости без требований конкретной задачи.
5. Не выполняй `git commit`, `git push`, `reset --hard`, обновление submodule, изменение секретов или удаление Docker volumes без отдельного разрешения.
6. В итоговом описании и Pull Request указывай `TASK-XXXX` и соответствующие `ADR-XXXX`.
7. Не исправляй несвязанные проблемы и не превращай открытые вопросы архитектуры в молчаливо принятые решения.

## Принятые рамки проекта

- Основной язык: Go. Продукт: поисковый движок с явно конфигурируемыми схемами индексов.
- Индексация/ingestion и поиск — разные логические потоки.
- Сначала REST ingestion, Kafka — отдельный адаптер в будущем.
- Lexical, semantic и image retrieval — отдельные сигналы; RAG не является обязательной частью поискового ядра.
- PostgreSQL/pgvector/FTS — предварительный поисковый backend, а не причина смешивать бизнес-логику с SQL.
- Tenant isolation, идемпотентность событий, совместимость embeddings и измеряемая задержка поиска — важные ограничения.
- Go-пакеты, точные API-контракты, SQL-миграции и ML-модели **пока не согласованы**.

## Качество (после появления утверждённого Go-кода)

- Применяй `gofmt`, устраняй проблемы `go vet` и `golangci-lint`.
- Добавляй тесты к изменениям, включая негативные случаи и ограничения изоляции tenants там, где это применимо.
- Выполняй `go test -race ./...`; для покрытия — `go test -race -covermode=atomic -coverprofile=coverage.out ./...`.
- Минимальный процент покрытия задаётся отдельно через переменную GitHub `MIN_COVERAGE`. Не повышай покрытие искусственными тестами ради цифры.
- GitHub Actions job `quality` — обязательная проверка для слияния после настройки защиты ветки. Не отключай её ради прохождения PR.
- Никогда не утверждай, что тесты, сборка контейнера или интеграция выполнены, если их реально не запускали.
